# CampusPulse dynamic registration + QR updates

## Improvements included
- Registration is shorter: the signed-in account's name and email are prefilled; email is read-only and only department needs to be entered.
- Prevents the same email from registering for the same event more than once (unless the prior ticket is cancelled).
- Checks event capacity before accepting a registration and shows live remaining-seat counts based on registrations loaded from Supabase.
- Generates a unique ticket code with `crypto.randomUUID()`.
- Ticket cards now render a real QR image encoding the ticket code (rather than a decorative QR icon), and include a QR download/open link.
- My Tickets and event “Going” indicators are scoped to the signed-in user's email; the check-in desk retains the registration list for verification.
- Print styles help save the ticket as PDF from the browser print dialog.

## QR behavior
The QR encodes only the ticket code, so a QR reader displays the same `SCEM-XXXXXXXX` code accepted by the Check-in Desk. QR images are generated by QRServer at runtime and therefore need internet access. For production, replace the public QR image endpoint with a locally generated QR library and enforce organizer-only check-in policies in Supabase.

## Supabase notes
The existing database migration must already be applied and the `events` and `registrations` tables must exist. Capacity checks are client-side for this student-project version; a production deployment should enforce capacity and duplicate registration atomically with a database function/unique constraint to prevent simultaneous booking races.
- Added Supabase Realtime subscriptions for `events` and `registrations`, so the app refreshes its lists and seat counts when rows change (Realtime must be enabled for these tables in the Supabase dashboard).
